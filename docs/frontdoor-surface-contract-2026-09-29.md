# Front door and surface discussions

This supersedes the visible island/sidecar behavior in the September 28 Monochat direction. Monochat is shared routing infrastructure. It must not replace the GUI surfaces with a single floating chat.

- Plan comments, draft comments, code-review annotations, page discussions, missions, and Memory Ask keep their own composers and histories at their source. “Discuss with Claude” opens the anchored discussion in place.
- A compact 144 × 32 capsule is centered inside the existing footer row as a fixed overlay, alongside the Send to Claude / approval controls. Its hit target is 160 × 40. There is no extra strip, no increase to footer height, and no loss of workspace height. The status and action groups keep clear of the center; narrow groups scroll horizontally. The pill has no review-count badge. It lifts subtly inside its fixed hit region as the pointer approaches. Only the membrane transforms; the click target, document, footer, and native browser bounds remain fixed.
- Hover and keyboard focus on the footer pill do not open a chat. Click, Shift+Enter, or Cmd-J opens an opaque full-screen view with centered conversation content. There is no title, welcome copy, header, or suggestion grid. Shift+Enter captures input from workspace editors and terminals, and is forwarded from embedded browser pages including subframes. Inside the open front door it remains a newline. IME composition and modified send shortcuts are preserved. An empty chat centers its composer. Focusing the home composer preserves its position and dimensions while the backdrop fades in; it does not replay a pill-to-screen animation.
- A fresh app session starts at an empty composer. Saved and recently used chats are never selected automatically; History opens a conversation only when chosen. A started or selected exchange survives tucking the front door away and reopening it. Deleting the current chat returns to the composer without selecting another conversation.
- Clicking outside the visible context box, the bottom return pill, or Escape closes the front door in one step and restores prior focus. There is no close X. Text-selection drags ending outside do not dismiss the chat. Menus and dialogs handle their own dismissal first. Surface navigation closes the front door, preserving the conversation, draft, and attachments.
- The focused front door preserves window dragging through transparent outer hit regions: the existing title-bar reach at the top and the shell's 10 px edges at the sides and bottom. Dragging retains composer focus and does not dismiss the chat; double-clicking the top region invokes the existing window zoom behavior. These regions add no layout space, border, hover treatment, or other visible styling.
- A visible New chat button returns from a saved conversation to the fresh composer. It leaves history and unsent text intact, and does not create another conversation until a message is sent.
- Saved conversations also keep a labeled History control. Activity & usage is a named action under More, with no unlabeled usage icon beside New chat. Its panel identifies the current conversation's usage, takes keyboard focus, and closes on Escape without dismissing the chat.
- The input grows with its text to half the viewport height, capped at 560 px and reduced further in short windows to leave room for controls. Beyond that cap, the text scrolls inside the input. Width and viewport changes recompute the input height.
- The model picker stays at its original width. Clicking or hovering a model reveals a compact 184 px effort strip beside the row; on narrow windows it fits below the row. Reopening the picker does not show effort merely because a model is selected. Hover previews light the notches cumulatively without changing the selected model or effort; clicking commits the model and effort together. Keyboard arrows preview and Enter/Space commit. Supported levels and defaults come from the provider catalog.
- Model discovery reads harness metadata with a 30-minute on-demand cache, preserves the last good result after refresh failures, and exposes a checked time plus Refresh models. It does not spend model tokens or fetch on hover. Details, source boundaries and validation are in `model-catalog-freshness-2026-09-29.md`.
- Front-door visibility is independent of surface dock visibility. Shared routing metadata does not contain UI redirection callbacks and is memoized.
- Pointer motion over the footer pill uses one scheduled animation frame and direct transform variables, with no React state updates or pointer-driven native overlay region updates. The fixed native hit region is registered when the pill is shown. Opening from the pill uses a short, gentle entrance; focusing the visible home composer only fades the backdrop. Reduced-motion preferences disable both motions.
